# Monori 痛點簡報（給外部協作用）

貼給其他 AI／設計師／文案時用這一份，內容不依賴任何對話脈絡。

---

## 產品是什麼

Monori 是一個 iOS App，本質是「閱讀殼層」。它讓使用者用**自己的帳號**，在 App 內建的瀏覽器登入 Patreon、Google Docs、AO3、方格子（Vocus）、AsianFanfics，把一部連載的**章節目錄**匯入本機書庫，然後用乾淨的排版閱讀。

所有資料只存在使用者自己的手機上。沒有後端伺服器，沒有帳號系統，沒有雲端同步。目前用側載方式安裝，正在準備上架。

## 使用者是誰

在網路上追連載的讀者。同人小說、原創網路小說、付費訂閱的連載都算。特徵：

- 同時追的作品散在三到五個不同平台
- 主要用手機讀
- 有些是付費訂閱者（例如 Patreon 會員），對支持創作者這件事有在意
- 不是技術使用者

## 痛點（核心）

**1. 追的東西散在好幾個平台，沒有一個地方能回答「我在讀什麼」。**
一部在 Patreon，一部在 AO3，一部在方格子。每個平台的介面不一樣、導覽邏輯不一樣、登入狀態各自獨立。瀏覽器書籤夾救不了，因為書籤記的是網址，不是「我讀到哪一章」。

**2. 這些平台的頁面不是為了讀長文設計的。**
一篇連載的頁面上通常有：創作者頭像與名稱、訂閱層級標籤、按讚／留言／分享數、留言串、推薦文章、平台自己的推廣橫幅、廣告版位。真正的正文往往只佔畫面的一小部分。字級是平台決定的，行距是平台決定的，讀者沒得調。

**3. 找下一章很麻煩。**
讀完一章，要捲回頁尾找連結，或退回目錄頁重新點。有些平台的目錄要一直往下捲才會載完。

**4. 讀到哪要自己記。**
瀏覽器沒有「這一章我讀到一半」這個概念。關掉分頁就沒了，下次要重新找。

**5. 更新了不會有人告訴你。**
想知道有沒有新章節，只能自己一個一個平台回去戳。

**6. 現有的替代方案代價太高。**
市面上的聚合器／爬蟲工具，通常要你交出帳號密碼、把內容存到它們自己的伺服器、或乾脆做盜版。對於有在付錢支持創作者的讀者來說，這些都不能接受。

## Monori 怎麼解

- **一個書庫**，五個來源的連載收在同一個列表，每一列有來源圖示、書名、作者、章數
- **匯入章節目錄**到本機，不必每次回平台找
- **乾淨的閱讀器**：預設隱藏工具列，只剩正文；字級與行距使用者自己調
- **上一章／下一章**在底部工具列，一鍵接續
- **每章各自的書籤**，關掉 App 回來還在原處
- **追更狀態**（追更中／已完結／棄坑）＋**未讀標記**，有新章節時書庫會亮起來
- **每個來源獨立的登入狀態**，切換來源不會弄丟其他來源的瀏覽紀錄

## 刻意不做的事（很重要，不要當成缺點寫，這是產品定位）

- 不繞過任何付費牆或存取控制。使用者必須本來就有權限看那些內容
- 不擷取 cookie、不攔截封包、不呼叫平台的官方或內部 API
- 不把內容存到 Monori 的伺服器，因為根本沒有這個伺服器
- 不做離線閱讀（刻意的設計）
- 不做匯出、不做跨使用者分享
- 每個使用者自己簽署 App、用自己的帳號登入

## 目前的限制（誠實揭露）

- 自動檢查新章節目前只有 Patreon 支援，其他來源是手動「檢查新章節」
- 平台改版可能讓閱讀器樣式或匯入失效，兩者都會優雅降級（閱讀器退回原始頁面；目錄可以重新匯入）
- 沒有離線閱讀

## 視覺基調

安靜、留白多的閱讀工具。單一鼠尾草綠 `#A8B9A0` 為品牌色，文字用 `#1C1B19`（不用純黑）。介面往後退，讓正文是主角。不是媒體 App，是「安靜的私人圖書室」。

## 一句話版本

**你追的連載散在五個網站，而那五個網站沒有一個是為了讓你好好讀完一章而設計的。**
